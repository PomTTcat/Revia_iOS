## 技術と実行

- SwiftUI によるネイティブアプリ。最低対応は iOS 17。システムの SQLite、Keychain、AVFoundation、UserNotifications を利用します。
- RxSwift / RxRelay 6.10.2 は Swift Package Manager で管理し、音声リクエスト、キャンセル、有効化条件の組み合わせに使用します。
- Expo、Node.js、CocoaPods、開発サーバーは不要です。旧 Expo アプリとはサンドボックスが異なり、自動移行は行いません。
- Xcode 26.3 以降の互換バージョンを推奨します。`Revia.xcodeproj` を開き、Revia target の Signing & Capabilities で自分の Team と必要な Bundle Identifier を設定します。
- 実機の開発者モードと署名を設定して実行します。Debug / Release とも開発サーバー不要です。保存済みデータはオフラインで利用できますが、新しい音声の生成には通信が必要です。

## 画面と操作

タブはカレンダー、今日、すべての文章、設定の4つです。日付を選ぶと当日の内容を表示します。今日の画面は日付変更とフォアグラウンド復帰で更新します。9か月一覧とピンチ操作は削除済みです。

カレンダーの追加を表す緑の点は学習日が今日の場合のみ緑で、過去の日付は灰色になります。文章カードも今日の新規文章だけ緑、復習は灰色です。ダークモードでは濃い緑と灰緑に切り替わります。「復習済み」や完了チェックインの状態はありません。

すべての文章は原文・意味で検索でき、実際の追加日時の新しい順で並びます。カードに追加日時を別途表示しません。表示する日付は時分秒を省きますが、内部の時刻は保持します。学習日は読み取り専用で、追加した入口の日付を使います。カレンダーから別の日付に追加できます。

共通カードには再生・停止、復習リセット、右上の「×」による削除、折りたためるメモがあります。メモの初期折りたたみは設定で変更できます。文章の削除は復習周期と音声メタデータにも反映し、参照状況に応じて音声ファイルを削除します。

設定には言語、外観、メモの折りたたみ、学習プラン、毎日の通知、声の種類、API Key の状態、読み込み・書き出し、音声容量を表示します。キー、バックアップ、通知、プラン編集は詳細画面です。Voice ID の手動入力、全音声リスト、モデル表示は現在 UI に出していません。

## 復習ルールとカスタムプラン

標準プランは計15回です。学習日の1・3・7・14・30日後に復習し、5回目の日付を基準に、その後は暦月ごとに10回予定します。該当日がない月は月末とし、翌月以降は元の基準日で計算します。

プランは標準1件とカスタム2件の計3件までです。カスタムには名前を付け、1・2・3・4・5・6・7・15・30日のブロックを加算して「復習」ポイントを置きます。`1 → 復習 → 2 → 復習` は学習日の1日後と3日後です。ポイントは予定日であり、完了操作ではありません。

カスタムは1～15ポイントで、各ポイントの間に1日以上必要です。最後は復習ポイントで終えます。15回への自動補充や月次予定の追加はしません。文章を追加するときに選択し、文章ごとに独立したスナップショットを保存します。テンプレートを変更・削除しても既存の文章は変わりません。

テンプレートは UserDefaults の `study.plans`、文章のプランは SQLite の `sentence_plans` に保存します。テンプレート一覧そのものは文章バックアップから復元しませんが、読み込んだ文章は自分のルールと名前を保持します。

## 復習のリセット

リセットはタップした当日を起点に文章の保存済みプランで再設定し、成功後に説明を表示します。標準の文章には標準ルール、カスタムの文章には保存済みスナップショットを使います。

元の学習日、追加日時、原文、意味、音声は変更しません。旧周期のリセット当日までの日付を残し、それ以降の未来の予定を無効にします。元データは削除しません。新しい周期は当日から表示し、同日の繰り返しでは周期を増やしません。元の学習日にリセットしても当日の復習カードを重複表示しません。

`review_cycles` と `cycle_reviews` に周期を追加保存し、最初の予定は `reviews` に残します。有効日程は過去と現在の周期を統合し、無効になった未来の予定を除外します。再起動時に旧予定を再計算・補充してはいけません。

## ローカルデータ

- DB：Application Support/revia.db。外部キーと WAL を有効にします。
- 音声：Application Support/Speech。
- 主なテーブル：`sentences`、`reviews`、`sentence_plans`、`review_cycles`、`cycle_reviews`、`audio_records`。
- 現在の schema は5です。3未満の旧 schema にだけ復習日の補充を行い、その後は実際の日付を保って読み込み・リセットを壊さないようにします。
- SQLite の旧列名 `japanese` は互換性のため残していますが、任意言語の原文を保存します。Swift 側では `text` を使います。
- 言語、外観、メモ、通知、テンプレート、声の設定は UserDefaults、API Key は Keychain に保存します。
- クラウド同期はありません。アンインストールすると端末内サンドボックスのデータは削除されます。

## ElevenLabs と音声キャッシュ

モデルは `eleven_v3`、出力は `mp3_44100_128` です。男性 George は `JBFqnCBsd6RMkjVDRZzb`、女性 Sarah は `EXAVITQu4vr4xnSDxMaL`。選んだ声を利用できるアカウント・キーが必要です。

キーは Keychain の WhenUnlockedThisDeviceOnly で保存し、SQLite、バックアップ、ログに書きません。変更・削除時は生成を無効にします。確認では選んだ声で `Hi.` を生成するため少量のクレジットを使いますが、試聴の自動再生・保存はしません。必要なのは Text to Speech 権限のみです。音声一覧の読み取りは任意で、失敗しても TTS の確認成功を取り消しません。`missing_permissions` は無効なキーと区別します。

有効なキーと声がある場合、追加画面で音声生成を初期選択し、解除もできます。文章を先に保存し、音声生成の失敗は通知します。後から再生で再試行しても文章は重複追加しません。送るのは原文のみで、意味は送りません。

再生は文章の既存ローカル音声を優先し、ファイルがなければ生成します。声の変更は新しい生成にだけ適用し、既存音声を強制再生成しません。キーがなくても端末の音声は再生できます。

ファイル名は MD5 ではなく `SHA-256(キャッシュ版 + NUL + 声 + NUL + モデル + NUL + 原文) + .mp3` です。日付と意味は含めません。同じ原文・声・モデル・版は共有できますが、空白と句読点もハッシュに影響します。最後の参照を削除したときに共有ファイルを消し、起動時に未参照 MP3 を整理します。保存前にデコードできることを確認します。

## 機種変更用バックアップ

設定 → 読み込みと書き出し。書き出しはシステム共有から AirDrop、メッセージ、「ファイル」への保存などが可能です。読み込みはシステムのファイル選択を使います。UI では JSON などの実装用語を出しません。

文章と予定だけを含み、音声、API Key、ローカルの自動採番 ID、アプリ設定は含みません。各文章は `text`、`translation`、`learningDate`、`createdAt`、実際の `reviewDates` と、必要に応じて `resetCycles`・`studyPlan` を持ちます。

- 版1：カスタムプランやリセット周期のない基本文章。
- 版2：リセット周期を含む文章。
- 版3：カスタムプランのスナップショットを含む文章。リセット周期も併せて保存できます。

現在は版1～3を読み込めます。全件追加で、重複排除・上書きはしません。同じファイルを再読み込みすると重複します。学習日・復習日は `YYYY-MM-DD`、追加・リセット日時は UTC です。復習日は原状復元し、再計算しません。全体検証後にトランザクションで書き込み、失敗時の部分追加を防ぎます。

## ローカル通知

設定 → 毎日の学習リマインダー。初期時刻は現地19:00、スイッチは初期オフです。ユーザーがオンにしたときだけ通知・音の権限を要求します。拒否済みの場合はシステムの通知設定へ案内します。固定 ID の `UNCalendarNotificationTrigger` を1件だけ毎日繰り返し、時刻変更で置き換え、オフで取り消します。

APNs、サーバー、リモートプッシュの entitlement は使いません。オフライン・アプリ終了中もシステムが通知できます。表示・音はシステム設定、集中モード、通知の要約に従います。復帰時に権限と現在言語の通知内容を同期します。

## 言語・外観・起動

英語、簡体中国語、日本語に対応します。初回は対応する端末言語を選び、非対応言語は英語に戻します。変更は即時で再起動不要です。文章の翻訳や復習予定の変更はしません。文字列キーは短い英語 snake_case とし、三言語と書式指定子を揃えて更新します。

外観はシステム（初期値）、ライト、ダークに対応し、即時反映・保存します。`Shared/Palette.swift` の動的な意味別カラーを再利用し、白固定の入力欄やダーク時の低コントラストを避けます。

システムの Launch Screen は暗い脳アイコンと Revia の静止画面です。アプリ内では3点を1→2→3→1とつなぐ光を1.6秒、徐々に減速させてからフェードアウトします。「視差効果を減らす」場合は光のアニメーションを省きます。カレンダーの追加ボタンはシステムのズーム遷移を使い、旧OS・動きを減らす設定では通常表示に戻します。

## 検証・保守

- 対応するシミュレーターまたは署名済み実機を選び、Xcode の Command-U でテストします。
- `xcodebuild -project Revia.xcodeproj -scheme Revia -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build-for-testing` で端末・テスト target のコンパイルを確認できます。これは実機テスト実行とは異なります。
- 日付・月末、SQLite、キャッシュ、バックアップ版、リセット周期、プラン構築と上限、翻訳、HTTP モック、通知調度をテストしています。
- 実際の TTS、スピーカー、権限、通知の到達、アニメーションの操作感、三言語のレイアウトは端末で確認します。モック検証を実際の API 検証として記録しないでください。
- DB 変更では既存データ、再起動、読み込み、連鎖削除、プランのスナップショットを確認します。ルール変更で既存文章を再計算しないでください。
- Commit メッセージは日本語とし、commit / push はその時点のユーザーの許可に従います。
